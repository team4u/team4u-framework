# Team4u 1.0 Breaking Changes

| Version | Breaking change | Migration |
| --- | --- | --- |
| 1.0 | Mask split into core, Jackson adapter, and dynamic config; unknown policies fail closed | Add `team4u-mask-jackson` for unchanged `com.team4u.framework.mask.jackson` FQCNs and `team4u-mask-config` for config rules. `MaskBootstrap` moved to `com.team4u.framework.mask.config.MaskBootstrap` with no old compatibility class. Unknown/null/empty/whitespace policies throw `IllegalArgumentException`; use explicit `NONE` for intentional plaintext. |
| 1.0 | Router declarative proxy APIs moved to team4u-router-proxy | Add `team4u-router-proxy` for `@Routed`, `@RouteContext`, `RoutedProxyFactory`, `RoutedBeanLocator`, `BeanResolver`, and `RoutedMethodInterceptor`; FQCNs are unchanged. Keep `team4u-router` for RoutingManager, policies, trace, and interceptors; translator routing stays on router core. |
| 1.0 | Translator passes neither router-proxy nor a JSON provider | Keep `team4u-translator` for response translation and add `team4u-router-proxy` separately only for declarative routed proxies. Add `team4u-serializer-jackson` or a custom registered `JsonSerializerPolicy` for JSON route policies. |
| 1.0 | Typed Space APIs moved to team4u-kv-space and HotSwapStore no longer implements proxy Swappable | Add team4u-kv-space for Space, Spaces, and SpacePolicy. Cast HotSwapStore.wrap(...) results to com.team4u.framework.kv.HotSwap instead of proxy Swappable; the proxy interface set is fixed at wrap time. |
| 1.0 | team4u-proxy no longer passes ByteBuddy transitively | Interface-only consumers need no change. Concrete-class proxy consumers must add `net.bytebuddy:byte-buddy` explicitly; this also applies to team4u-log-governance and retry-proxy. `team4u-config-proxy` owns ByteBuddy at runtime, so adding that adapter alone is sufficient for config class proxies. |
| 1.0 | team4u-log removed and split into core/governance | No compatibility artifact remains. Add team4u-log for unchanged core/appender/pipeline/support FQCNs and plain-toString output; add team4u-log-governance for unchanged bootstrap, Jackson, Config, Mask, Proxy, and Spring FQCNs. Governance owns the explicit Jackson provider runtime edge. |
| 1.0 | Log reset and serialization semantics changed | LogEngine.reset does not stop LogBootstrap governance; call LogBootstrap.stop explicitly. Core LogEngine.toJson may be plain text unless a serializer is installed; governance installs Jackson and requires its provider/Jackson runtime. |
| 1.0 | Core entry points use bare artifact IDs and adapters use suffixes | Depend directly on concrete artifacts managed by the root BOM (e.g. team4u-config, team4u-kv, team4u-lease, team4u-log, team4u-retry, team4u-ratelimiter, team4u-singleflight). Bare coordinates no longer serve as grouping/aggregator artifacts. |
| 1.0 | Managed retry and config-driven retry policies moved out of retry-core | Add team4u-retry-managed for ManagedRetries, ManagedRetryClient, managed records/store APIs, and ManagedSubmitResult; add team4u-retry-config for DynamicRetryPolicyRegistry. Retries now supports INLINE only, and the moved retry FQCNs change as documented in MIGRATION-1.0.md. |
| 1.0 | Root POM is the only BOM | Import com.team4u:team4u-framework:type=pom; do not import a separate BOM. |
| 1.0 | ConfigManager.Builder.configBinder(...) removed; ConfigProxyCreator is required for createProxy | Use DefaultConfigBinder.bind(...) directly for pinned POJOs, and add team4u-config-proxy for automatic ServiceLoader creator discovery or provide a ConfigProxyCreator. createProxy no longer falls back to binding. |
| 1.0 | Config proxy and Spring adapters moved out of config-core | Add team4u-config-proxy for ConfigProxyFactory/SnapshotAware. Add team4u-config-spring and explicitly import Team4uConfigConfiguration; no Boot auto-configuration metadata is provided. |
| 1.0 | ConfigManager.global() is lazily initialized and ConfigBootstrap refreshes initialized globals on registration/lock | Keep bootstrap registrations before application use; late registrations before lock are reflected without caller-side refresh. |
| 1.0 | Serializer API no longer implies a Jackson runtime provider | Add com.team4u:team4u-serializer-jackson explicitly, or register/provide a custom JsonSerializerPolicy via ServiceLoader for general JSON APIs. The Task 7 no-provider error names both choices; upstream libraries own no runtime provider except the explicit `team4u-log-governance` runtime adapter. |
| 1.0 | JDBC utilities moved from team4u-base to team4u-base-jdbc | Add com.team4u:team4u-base-jdbc; all JDBC FQCNs are unchanged. |
| 1.0 | Criterion wildcard matching moved from Spring AntPathMatcher to Base PathPatternMatcher | DSL behavior and the locked 53-case matrix are unchanged; call Base `PathPatternMatcher` directly for pure Java path matching. |
| 1.0 | Removed Team4uCriterionAutoConfiguration | The criterion artifact no longer carries Spring integration; expose required global singletons with application configuration. |
| 1.0 | Consumer gates are staged during convergence | consumer-it/release-contracts run minimal, config-core, serializer-api, serializer-jackson, interface-proxy, log-governance, ratelimiter-core, and singleflight-jackson (8 consumers). The config-core consumer proves the proxy-free core boundary; the log-governance consumer proves the transitive runtime provider; the ratelimiter-core consumer proves the three-way ratelimiter core boundary; the singleflight-jackson consumer proves the singleflight split with an application-owned JSON provider. |
| 1.0 | team4u-ratelimiter monolith split into core/proxy/spring | Add `team4u-ratelimiter` for the engine and facade, `team4u-ratelimiter-proxy` for `@RateLimit` annotation interception, and `team4u-ratelimiter-spring` for `@EnableRateLimit`. FQCNs keep their `com.team4u.framework.ratelimiter.*` packages; rule JSON requires an explicit application-provided `JsonSerializerPolicy` (e.g. `team4u-serializer-jackson`). |
| 1.0 | team4u-singleflight monolith split into core/proxy/spring | Add `team4u-singleflight` for the engine and facade, `team4u-singleflight-proxy` for `@SingleFlight`, and `team4u-singleflight-spring` for `@EnableSingleFlight`. Core carries a direct nonoptional `jackson-databind` edge for its durable session schema (inherited by adapters) but never passes `team4u-serializer-jackson`; rule JSON requires an explicit application provider. |
| 1.0 | NamedKvStoreRegistry and NamedKvStore moved from team4u-kv to team4u-kv-space | FQCNs are unchanged (`com.team4u.framework.kv.*`); add `team4u-kv-space` (or any of team4u-id / ratelimiter / singleflight, which pass it transitively) to keep using named stores. |
| 1.0 | New artifacts team4u-id and team4u-proxy-spring | `team4u-id` provides config-driven sequence generation on kv `CounterCapable` (counting backends stay explicit). `team4u-proxy-spring` provides the annotation-proxy Spring wiring template (`AnnotationProxyBeanPostProcessor`); it never carries ByteBuddy at compile/runtime and is shared by ratelimiter-spring / singleflight-spring. |
| 1.0 | Final reactor and BOM manage 48 leaves | The root POM is the only BOM and now manages 48 concrete leaves (40 after Task 18 plus id, ratelimiter core/proxy/spring, singleflight core/proxy/spring, and proxy-spring). Depend on concrete artifacts only. |
