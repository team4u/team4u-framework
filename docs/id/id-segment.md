# 本地号段

直连计数模式下每次取号都访问底层计数器，高并发场景存在两类开销：

- 数据源访问：每次 `next` 一次网络往返（JDBC/Redis）；
- 计数竞争：所有实例争抢同一计数行/键（行锁排队、Redis 热键）。

规则配置 `segment`（号段长度）大于 0 时启用号段模式：一次从计数器批量取回 N 个序号缓存本地，取号直接走本地内存，号段耗尽再取下一批。

```text
next ──► 本地号段 cursor/end ──耗尽──► incrementAndGet(key, N, 0) ──► 计数器(直增 N)
              │
              └── 未耗尽：CAS 发号，零存储访问、零锁竞争
```

收益（以 `segment=100` 为例）：

- 数据源访问量降低 100 倍：每 100 个序号仅 1 次存储访问；
- 竞争范围缩小：实例间仅在号段切换时竞争一次。

代价：

- 趋势递增而非严格递增：多实例同时取号段时序号整体趋势增长，单实例序号会领先/落后其他实例；
- 号段空洞：实例重启或规则热更新后，已取回未用完的号段作废（号段模式的固有语义，追求连续无空洞应直连计数）。

## 机制

### 惰性取段，零常驻线程

号段实例（`LocalSegment`）仅持有两个变量：已发出的最大位置 `cursor`（`AtomicLong`）与当前段上界 `end`。本地段耗尽时才在实例锁内取下一批——没有后台生产者线程，也就没有队列、清理器、超时参数这一整套常驻资源。

### 并发模型

- 发号路径：`cursor` CAS 无锁递增，读路径零竞争；
- 段切换：实例锁内串行执行 `incrementAndGet(key, segmentSize, 0)`（TTL 传 0 = 永不过期，周期重置靠换键），取段返回值即段边界，天然 singleflight；
- 游标不回退：`cursor` 单调递增，段切换仅发布新的 `end`，不存在「回写游标」路径，杜绝重复发号。

### 耗尽标记

设置了 `maxValue` 且未开启循环时，取段后发现段起点越过耗尽线（或发出的位置越过耗尽线）即标记耗尽：后续取号直接返回 `null`，不再访问存储。

### 实例生命周期

号段实例由 `SequenceService` 的 LRU 缓存管理（默认容量 1024，构造参数可调），缓存键为 `规则标识@分组标识@规则指纹`：

- **分组轮转**：按天/月分组时，旧分组的键不再被访问，实例被 LRU 自然淘汰，无需过期配置与清理线程；
- **规则热更新**：缓存键含规则内容指纹，规则变更后新取号走新号段实例，旧实例连同未用完的号段一起淘汰。

## 配置建议

- `segment` 即号段长度，常见 100~1000：太小达不到批量收益，太大加剧空洞与趋势跳跃；
- 高频序号（消息号、流水号）建议 `segment=500` 以上；低频序号直连即可（不配置 `segment`）；
- 追求严格连续的序号（对账单号等）不要开启号段模式，直连 JDBC 计数；
- 分组粒度细（如按商户）且活跃分组多时，控制 `segment` 大小并确认 LRU 容量（默认 1024 个号段实例）足以容纳活跃分组，避免频繁取段；
- 实例重启丢号段属正常现象：只要业务侧接受趋势递增，空洞无影响。

## 与直连模式的一致性

两种模式对外语义完全一致（同一套契约测试强制）：相同的规则配置下，第 N 次取号返回相同的序号值；耗尽、循环、分组行为不因模式而异。仅存的差异是存储访问次数与多实例间的序号交错。
